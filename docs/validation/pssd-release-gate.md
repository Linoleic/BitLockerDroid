# PSSD 发布前实机回归

日期：2026-10-24。**当前结果：未通过，存在免 Root 写入阻塞项。**

## 环境与范围

- 小米平板 6SP，Android 16，无线 ADB；HIKSEMI P202 / RTL9210（0bda:9210），ZHITAI Ti600 1TB。
- 已安装的 Release 测试包（v1.1.1 / versionCode 122，无 DEBUGGABLE 标志）。应用逻辑与 `909a14f` 一致，后续提交仅涉及文档；未发布版本。
- 6 个已保存凭据的卷：NTFS、exFAT、FAT32 各覆盖 CBC / XTS。通过主页操作工作模式，不直接修改模式偏好。
- 每卷仅操作一个随机命名的独立测试文件，每次写入 2MiB 随机数据，以长度及 SHA-256 校验。没有覆写原有用户文件。

## 已通过

- Root 下六卷写入及立即回读全部一致。
- Root 持续刷新与六卷文件校验 **323.49 秒、9 轮**，会话、USB 连接、进程及 Wi-Fi 正常。
- 从主页确认安全关闭并重启，完成 Root → 免 Root；六个卷使用保存凭据恢复，实际路径均为 `usb://`。
- 保存凭据及附属条目哈希与初始记录一致，切换后没有额外请求 USB 授权。
- 免 Root 读回 Root 写入的六个文件，长度和 SHA-256 全部一致。
- 免 Root 覆写 EC 卷测试文件后，等待写入完成，再次回读的长度和 SHA-256 一致。
- 免 Root 授权监测 **647.72 秒、268 次采样**，未发生授权丢失或意外进程重启。此项只证明授权/进程状态，不能据此认定读写通道稳定。

## 失败与观察

1. 首次免 Root 写入 EC 后，立即回读触发 `VolumeWriteState.awaitPath` 的写入未完成保护。ADB `content read` 随后显示空文件句柄异常。等待后校验成功，因此这次不能认定为文件内容错误；测试脚本已补充等待。
2. 随后的卷信息查询曾超过 120 秒，稍后恢复。尚未证明死锁，也未确认空间统计是否为主要耗时来源。
3. 免 Root 覆写 EX 卷时，FatFs 在文件 offset 0 报错：`Batch block write failed: expected 131072, got -1`。随后出现 USB bulk IN/OUT 失败、SCSI 重试耗尽，native fd 通道被标记为 poisoned，写入客户端收到 EPIPE。
4. 对失败卷请求正常安全关闭，返回 `success=false`，明确提示文件传输失败；未强行终止应用或复位设备以绕过此保护。

这里的 128KiB 是逻辑批量写请求，不是单次 USB bulk 大小；当前 bulk 传输仍按最多 16KiB 切分。不能仅凭请求长度认定超限。

源码审查另确认：`UsbStorageManager.UsbBlockDeviceWorker` 的异步分支在写任务入队后即返回成功 ACK，SCSI 失败会稍后才传播。它存在完成语义风险，**但尚不能认定为本次 bulk 失败的已证实根因**；需要进一步核对失败阶段、分块及超时。不能用延长超时或提前报成功来消除测试失败。
