# SMART 完整性与查询诊断验证

日期：2026-10-24。代码提交：`3fdb4f6`（原生校验）、`48deaba`（应用复核与查询诊断）。

## 实现

- ATA SMART 页要求 512 字节、不是全零或全 FF，且全部字节之和模 256 为 0。原生读取与 Kotlin 解析分别复核，不能仅凭后端的“校验通过”标记接受坏页。
- 读取失败与校验失败分别报告。校验失败保持“待确认”，清除健康度、温度及计数解读，完整原始页保留为未信任的诊断字节；复制文本包含不作健康解读的说明。
- NVMe 保留已有日志结构和合理性检查，不套用 ATA 校验和。界面单独显示“NVMe 日志结构检查通过”，不会将其称为校验和通过。
- 查询结果显示完成时间、耗时和失败阶段。耗时使用单调时钟；成功和失败均记录时间，取消操作不生成完成结果。阶段包括授权、连接、设备占用、协议支持、读取、数据校验和响应解析。
- 手动 Root 查询会重新确认 su 授权；USB 查询检查当前 Host 授权。既有桥接白名单、关闭卷后才可查询及禁止失败后重复探测的保护保留。
- 弹窗状态按设备路径和 USB ID 隔离；首次查询使用可取消的效果，刷新始终在 finally 中结束加载状态。没有加入后台轮询或历史快照。

校验算法参考 [smartmontools 的 ATA SMART 读取与校验实现](https://www.smartmontools.org/static/doxygen/atacmds_8cpp_source.html)。校验通过只表示数据页满足该校验规则，不证明硬盘健康，也不验证厂商属性含义。

关键文件：`SmartQueryDiagnostics.kt`、`SmartDataParser.kt`、`SmartHealthManager.kt`、`SmartHealthInfo.kt`、`UsbSmartProbe.kt`、`SmartHealthDialog.kt`、中英文资源和 `native/daemon/smart_reader.c`。
